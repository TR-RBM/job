# job syntax reference

Generated by `job help --syntax` from the shared command definition. Change the definition, not this file.

## Global options

Written before the command, as in `job --system status 7`.

| Option | Meaning |
|---|---|
| `--system` | use the system service, as JOB_SYSTEM=1 does |

## Execution

### job run

execute a command and wait for it.

    job run [OPTIONS] -- COMMAND [ARG...]

| Option | Meaning |
|---|---|
| `-q, --queue PATH` | the Queue to use |
| `--label KEY=VALUE` | a label for classification; it never affects scheduling or policy |
| `--idempotency-key KEY` | a repeated submission with this key returns the first Job |
| `--dir DIR` | the working directory |
| `--session NAME` | the label of the calling session |
| `--shell SHELL` | run SHELL -c with the first argument as the script |
| `--legacy-shell` | let Bash interpret a single argument, as before |
| `--pty` | give the Job a persistent shared terminal |
| `--summary` | print the final diagnostic summary instead of live output |
| `--json` | print the result as JSON |
| `--budget DURATION\|none` | how long run waits before it returns 75 |
| `--time DURATION` | stop the Job after this long |
| `--priority N` | admission priority from -1000 through 1000 |
| `--execution-profile NAME@REV\|none` | a versioned execution profile |
| `--class NAME@REV\|none` | a versioned scheduling class |
| `--stdin` | pass the standard input of this command to the Job and close it at its end |
| `--on-interrupt forward\|detach\|cancel` | what the first SIGINT or SIGTERM does: pass it to the Job, leave the Job running, or cancel it |
| `--cores N` | cores to reserve |
| `--mem SIZE` | memory to reserve, for example 4G |
| `--pids N` | earlier spelling: reserve N processes and threads and limit the Job to them |
| `--write-budget SIZE` | bytes it may write before the service stops it; not a file system quota |
| `--disk SIZE` | earlier spelling of --write-budget |
| `--device NAME` | an exclusive device to hold |
| `--net default\|none\|URL\|ns:NAME\|profile:NAME` | the host network, none, a proxy or tunnel, a configured namespace or a named profile |
| `--net-secret-file FILE` | a private file with user:password for the proxy |
| `--bandwidth RATE` | network rate each way, for example 5Mbit |
| `--monitor M` | the monitor its windows belong on |
| `--on USER@HOST` | run on the job service of another host over ssh |
| `--ssh-key FILE` | the ssh key used with --on |
| `--ssh-option KEY=VALUE` | an ssh option used with --on |
| `--send PATH` | copy PATH to the other host before the start |
| `--fetch PATH` | copy PATH back from the other host after the end |
| `--confine` | let the Job write only in its own tree |
| `--allow-write PATH` | also allow writing under PATH; implies --confine |
| `--cpu-request N` | CPUs counted at admission |
| `--memory-request SIZE` | memory counted at admission |
| `--cpu-limit N\|unlimited` | CPU time limit in CPUs |
| `--cpu-weight N` | CPU weight from 1 through 10000 |
| `--memory-high SIZE\|unlimited` | memory throttling threshold |
| `--memory-max SIZE\|unlimited` | hard memory limit |
| `--memory-swap-max SIZE\|unlimited` | swap limit |
| `--pids-max N\|unlimited` | limit on the number of processes and threads |
| `--io-max MAJOR:MINOR,KEY=VALUE...` | I/O rate limits of one block device |
| `--io-weight MAJOR:MINOR=WEIGHT` | I/O weight on one block device |
| `--io-bfq-weight MAJOR:MINOR=WEIGHT` | BFQ weight on one block device |
| `--cpu-affinity LIST\|inherit` | CPUs the processes may run on |
| `--numa-policy POLICY` | NUMA memory policy |
| `--rlimit NAME=SOFT[:HARD]` | one resource limit of the processes |
| `--no-new-privs yes\|inherit` | forbid gaining privileges through exec |
| `--cap-drop NAME,...\|all\|inherit` | capabilities removed before exec |
| `--seccomp-deny NAME,...\|inherit` | system calls refused with an error |
| `--namespaces KIND,...\|inherit` | namespaces created for the processes |
| `--root read-only\|inherit` | make the file system tree read-only |
| `--private-tmp yes\|inherit` | give the processes their own empty temporary directories |
| `--writable PATH,...\|inherit` | paths that stay writable under a read-only root |
| `--output-head SIZE` | bytes kept from the start of each output stream |
| `--output-tail SIZE` | bytes kept from the end of each output stream |
| `--format text\|json` | json prints one versioned envelope with schema_version, kind and data |
| `-h, --help` | show this help |

| Exit status | Meaning |
|---|---|
| 0 | the Job succeeded |
| N | the exit status of the Job itself; 128+S when signal S ended it |
| 1 | the Job was cancelled or stopped by the service |
| 75 | the deadline passed while the Job was pending or running, or the service stayed unavailable |
| 125 | service failure, lost Job, start error or usage error |

With --format json the envelope kind is `run`.

### job release

    job release [OPTIONS] ID[-ID][,ID...]...

| Option | Meaning |
|---|---|
| `--dry-run` | show what would happen and change nothing |
| `--json` | print the result as JSON |
| `--format text\|json` | json prints one versioned envelope with schema_version, kind and data |
| `-h, --help` | show this help |

| Operand | Meaning |
|---|---|
| `ID[-ID][,ID...]` | one Job, an inclusive range such as 1-10, or a comma list such as 1,4,7-9 |

| Exit status | Meaning |
|---|---|
| 0 | success |
| 1 | with a set: a Job was refused or failed, an ID named on its own does not exist, or no Job of the set exists |
| 75 | with a set: a change is still pending |
| 125 | usage error or service failure; with one ID also a refusal |

With --format json the envelope kind is `release`.
